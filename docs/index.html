A better image fit is not automatically a better robot state.

KineSync-GS separates state estimation from state-changing authority. A kinematically bound Gaussian renderer estimates a bounded whole-state correction; cross-view or motion evidence verifies the proposal; the interface then commits the verified update or preserves the incoming measurement.

Proposal→Separate evidence→Verified update/Fallback

One synchronization contract

Spatial rendering and temporal motion expose the same auditable interface to Gaussian twins, simulators, and downstream policies.

01

Bounded proposal

Forward kinematics binds Gaussians to robot links. Multi-view inverse rendering or motion alignment estimates a coordinated correction within explicit bounds.

02

Proposal evidence

Cross-view support, visual gain, motion correlation, and state consistency determine whether the proposal supports a twin-level update.

03

Verified state update

The complete proposal is committed after verification. The shared fallback preserves the incoming measurement and records the decision.

Shared output

Architecture A · System flow
Asynchronous images and telemetry enter temporal association, bounded Gaussian recovery, separate evidence, and whole-state verification before one synchronized state is published.
Architecture B · Spatial path
Fixed kinematics, link-bound Gaussians, and calibrated cameras produce a fused proposal. View-specific estimates provide cross-view evidence for committing the complete proposal or retaining the measured state.
Architecture C · Temporal path
Image and telemetry motion features estimate lag after native-delay correction. Timing evidence then selects corrected resampling or preserves the original association.
